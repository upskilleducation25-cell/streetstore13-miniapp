# STREETSTORE.13 — Telegram Mini App

Інтернет-магазин одягу у форматі Telegram Mini App + адмін-панель + API.

| Пакет             | Що це                                | Стек                       |
| ----------------- | ------------------------------------ | -------------------------- |
| `apps/api`        | REST API, Telegram-бот, сповіщення   | NestJS, Prisma, PostgreSQL |
| `apps/miniapp`    | вітрина, що відкривається в Telegram | React, Vite, Tailwind      |
| `apps/admin`      | адмін-панель каталогу                | React, Vite, Tailwind      |
| `packages/shared` | спільні enum-и, статуси, гроші       | TypeScript                 |

Архітектура та план етапів: `docs/architecture.md`.

## Вимоги

- Node.js 22+ (`.nvmrc`)
- pnpm 10 (`corepack enable`)
- Docker (для PostgreSQL і Redis) або власний PostgreSQL 16

## Запуск локально

На Windows — покрокова інструкція для PowerShell: [`docs/local-setup-windows.md`](docs/local-setup-windows.md).

```bash
corepack enable
pnpm install

# База і Redis
pnpm db:up

# Змінні оточення API
cp apps/api/.env.example apps/api/.env

# Схема БД і довідники (категорії, бренди, кольори, розміри, доставка)
pnpm db:migrate
pnpm db:seed

# Усі застосунки одночасно
pnpm dev
```

| Адреса                       | Що              |
| ---------------------------- | --------------- |
| http://localhost:3000/health | стан API і бази |
| http://localhost:5173        | Mini App        |
| http://localhost:5174        | адмін-панель    |

Фронтенди проксують `/api` на `localhost:3000`.

## Адмін-панель

### Перший власник

Публічної реєстрації немає. Першого власника створює команда (пароль — від 10 символів,
передається тільки через env і ніде не друкується):

```bash
ADMIN_OWNER_EMAIL=owner@example.com \
ADMIN_OWNER_PASSWORD='довгий-надійний-пароль' \
ADMIN_OWNER_NAME='Власник' \
pnpm admin:create-owner
```

У PowerShell (Windows) змінні задаються інакше — див. [`docs/local-setup-windows.md`](docs/local-setup-windows.md#7-перший-власник-адмінки).

Команда ідемпотентна: якщо email уже є, нічого не змінює. Щоб скинути забутий пароль власника,
додайте `--reset-password` (акаунт стане активним власником, усі його сесії завершаться).
На сервері: `pnpm --filter @ss13/api admin:create-owner` після `prisma:deploy`.

Далі власник додає менеджерів на сторінці «Адміністратори».

### Ролі

| Що                                                    | Власник | Менеджер |
| ----------------------------------------------------- | :-----: | :------: |
| Товари, варіанти, залишки, фото, категорії, довідники |   так   |   так    |
| Адміністратори: додати, змінити роль, вимкнути, сесії |   так   |    ні    |
| Зміна власного пароля                                 |   так   |   так    |

Усі перевірки — на сервері (`AdminAuthGuard`): менеджер отримає 403 `FORBIDDEN_ROLE`,
навіть якщо викличе API напряму.

### Змінні оточення (apps/api/.env)

| Змінна                                                                   | Що                                                                                                                                                                         |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CORS_ORIGINS`                                                           | адреси адмінки й Mini App; запити адмінки, що змінюють дані, з іншого `Origin` відхиляються                                                                                |
| `ADMIN_SESSION_TTL_HOURS`                                                | строк сесії, за замовчуванням 12                                                                                                                                           |
| `ADMIN_COOKIE_SECURE`                                                    | `true` у продакшні за замовчуванням (тоді cookie `__Host-ss13_admin`); локально по http — `false`                                                                          |
| `ADMIN_COOKIE_SAMESITE`                                                  | `strict` (адмінка і API на одному сайті) або `none`, якщо вони на різних доменах (тоді потрібен `ADMIN_COOKIE_SECURE=true`)                                                |
| `TRUST_PROXY`                                                            | кількість проксі перед API (напр. `1`), щоб ліміт входу рахував справжні IP                                                                                                |
| `STORAGE_DRIVER`                                                         | `r2` — Cloudflare R2; `local` — тека на диску (тільки розробка, за замовчуванням поза продакшном); `none` — завантаження фото вимкнено (503), за замовчуванням у продакшні |
| `LOCAL_STORAGE_DIR`                                                      | тека для `local`, за замовчуванням `apps/api/uploads` (в `.gitignore`)                                                                                                     |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | доступ до бакета R2; ключі тільки на сервері, у браузер не передаються                                                                                                     |
| `R2_PUBLIC_URL`                                                          | публічна адреса бакета (власний домен або `r2.dev`), з неї віддаються фото                                                                                                 |
| `R2_ENDPOINT`                                                            | необов'язково: інший S3-сумісний endpoint                                                                                                                                  |

Адмінка в розробці ходить на API через проксі Vite (`/api`). Для окремого домену
задайте `VITE_API_URL` під час збірки адмінки (напр. `https://api.example.com/api/v1`).

### Фото

Сервер сам визначає формат за вмістом файлу (JPEG, PNG, WebP, AVIF, HEIC), не довіряючи
MIME від браузера; SVG і анімації відхиляються. До 10 МБ на файл, до 10 файлів за раз,
до 30 фото на товар, сторона від 200 px. Кожне фото зберігається як WebP 300/600/1200 px
без EXIF. Якщо сховище не налаштоване, завантаження повертає помилку — успіх не імітується.

## Правила даних

- Гроші зберігаються цілими числами в копійках (`2999 ₴` → `299900`).
- Склад ведеться по варіантах «товар + колір + розмір» (`product_variants`).
  `products.total_stock` оновлюється тригером у базі.
- Залишок не може стати від'ємним (CHECK у базі); усі операції зі складом — у транзакціях.
- Замовлення зберігає знімок товару (`order_items`), тож зміни каталогу не ламають історію.
