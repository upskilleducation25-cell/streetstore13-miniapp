# Звіт після етапу

Звіт пишеться після того, як PR відкрито і CI на GitHub зелений. Короткий підсумок іде в
повідомлення власнику, повний звіт — окремим файлом і в опис PR.

## Правила

1. Тільки факти. Що не запускалось — так і пишемо: **«не перевірено»** і чому.
2. Кожне «перевірено» має підтвердження: команда, тест, HTTP-запит з кодом відповіді.
3. Відхилення від погодженого плану — окремим пунктом, з причиною.
4. Мова — українська, без внутрішніх ідентифікаторів сесій.

## Шаблон

```markdown
# Етап N — <назва>: звіт

Гілка `<branch>` · PR <посилання> · коміт `<sha>` · CI: <зелений / червоний>

## 1. Структура

<дерево змінених частин монорепо, коротко>

## 2. Файли

Створені:

- `<шлях>` — <навіщо>
  Змінені:
- `<шлях>` — <що змінено>

## 3. Ендпоїнти / сторінки

| Метод | Шлях        | Опис | Авторизація                  |
| ----- | ----------- | ---- | ---------------------------- |
| GET   | /api/v1/... | ...  | публічний / покупець / адмін |

| Сторінка | Маршрут | Що на ній |
| -------- | ------- | --------- |

## 4. Міграції та дані

<нові міграції, зміни seed, або «немає»>

## 5. Що перевірено

| Перевірка                       | Як               | Результат                  |
| ------------------------------- | ---------------- | -------------------------- |
| lint / typecheck / build / test | `pnpm …`         | ✅ / ❌                    |
| <сценарій>                      | <тест або запит> | ✅ <код відповіді / вивід> |

## 6. Що НЕ перевірено

- <що> — <чому> (наприклад: немає Docker, немає реального токена бота, не відкривалось у Telegram)

## 7. Відхилення від плану

- <що і чому>, або «немає»

## 8. Що потрібно від власника

- <злити PR, дати токен бота, підтвердити перехід до етапу N+1, …>
```
