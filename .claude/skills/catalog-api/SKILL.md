# Публічне API каталогу

## Що віддавати

1. Публічні ендпоїнти повертають тільки товари зі `status = ACTIVE` і `deleted_at IS NULL`,
   тільки активні категорії та бренди. `DRAFT`, `HIDDEN`, `ARCHIVED` — ніколи, навіть за
   прямим `slug` (відповідь `404`, як для неіснуючого).
2. Службові поля не потрапляють у публічні відповіді: `sort_weight`, `views_count`,
   `sales_count`, `admin_note`, `search_vector`, внутрішні ключі сховища тощо.
   Відповідь формується явним маппером у DTO, а не віддачею Prisma-моделі.

## Наявність

3. Картка товару повертає матрицю `variants` (колір, розмір, `available`, за потреби
   залишок), щоб клієнт окремо знав доступність **кожного** кольору і **кожного** розміру
   в цьому кольорі. Недоступна комбінація показується як недоступна, а не зникає мовчки.
4. `inStock` товару = є хоча б один активний варіант зі `stock > 0`.
5. `GET /products/:id` віддає залишок (`stock`) кожної пари колір + розмір, щоб клієнт
   обмежив кількість. Показувати покупцю «залишилось N шт.» — тільки при низькому залишку
   (`inventory.lowStockThreshold`); це рішення UI, а не API.

## Гроші

6. Гроші зберігаються і рахуються як цілі копійки (`Int`) — це точно, як Decimal, без
   помилок округлення. `float` для грошей заборонений.
7. Формат у відповіді завжди однаковий: усі грошові поля (`price`, `oldPrice`, `lineTotal`,
   `total`…) — цілі копійки (UAH), це задокументовано в Swagger. Форматування для людини
   (`2 999 ₴`) робить клієнт через `formatUah()` з `@ss13/shared`.
   `oldPrice` присутній тільки якщо більший за `price`; `discountPercent` рахує сервер
   через `discountPercent()` з `@ss13/shared`.

## Запити

8. Кожен вхід (query, params, body) описаний DTO і валідується (Zod-схема або
   class-validator) до потрапляння в сервіс. Невідомі поля відкидаються.
9. Пагінація курсорна: `cursor` + `limit` (за замовчуванням 20, максимум 50).
10. Фільтри `GET /products`: `category`, `brand[]`, `color[]`, `size[]`, `minPrice`, `maxPrice`
    (копійки), `inStock`, `isNew`, `isPopular`, `isSale`; сортування `sort` = `new` |
    `price_asc` | `price_desc`. Це один спільний DTO (`ProductsQueryDto`), яким пізніше
    користується й AI-пошук (див. `ai-search-guardrails`). `color` і `size` мають збігатися
    в одному варіанті.
11. Невідомі значення фільтрів (неіснуючий slug бренду тощо) повертають порожній результат,
    а не `500`.

## Помилки

12. Єдиний формат для всіх помилок: `{ "code": "PRODUCT_NOT_FOUND", "message": "…", "details"?: … }`
    з правильним HTTP-статусом (`400` валідація, `401`, `403`, `404`, `409` конфлікт складу,
    `500`). Стек-трейси й SQL ніколи не повертаються клієнту.

## Документація

13. Кожен ендпоїнт і DTO описані в Swagger (OpenAPI): параметри, приклади, коди помилок.
    Новий ендпоїнт без Swagger-опису не вважається завершеним.
14. Публічне API версіонується префіксом `/api/v1`; ламаючі зміни — тільки в новій версії.
